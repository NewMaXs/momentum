# Security Policy

## 报告漏洞

我们严肃对待所有安全漏洞。感谢你帮助我们改进项目的安全性。

**请不要在公开的 GitHub Issues 中报告安全漏洞。**

为了负责任地披露漏洞，请通过以下方式与我们联系：

* 发送电子邮件至以下电子邮件之一:
  * [#](mailto:#)

### 报告中应包含的内容

一份有效的漏洞报告能帮助我们更快地定位和修复问题。请在报告中尽量包含以下信息：

* **漏洞类型**
* **受影响的组件或文件**
* **复现步骤**：提供清晰、详细的步骤来重现该漏洞。
* **概念验证 (PoC)**：如果可能，提供一个简单的代码片段或请求来演示此漏洞。
* **影响**：描述此漏洞可能造成的潜在影响。

收到报告后，我们会尽快确认收到，并与你合作解决问题。

## 披露政策

在收到安全漏洞报告后，我们的目标是：

1.  **确认**：在3个工作日内确认收到报告。
2.  **调查**：对漏洞进行调查和验证。
3.  **修复**：尽快开发修复程序，并准备发布安全更新。
4.  **披露**：在发布修复程序后，我们将公开发布安全公告，并对报告者表示感谢。

我们请求报告者在我们在官方渠道发布修复和公告之前，不要公开披露该漏洞的任何信息，以便为我们的用户提供足够的时间进行更新。

## Reporting a Vulnerability

We take all security vulnerabilities seriously. Thank you for helping us improve the security of our project.

**Please do not report security vulnerabilities through public GitHub issues.**

To report a vulnerability responsibly, please use the following methods:

* Email us at
  * [#](mailto:#)

### What to Include in a Report

An effective vulnerability report helps us identify and fix the issue faster. Please try to include the following information:

* **Type of vulnerability**
* **A detailed description**
* **Steps to reproduce**: Clear and detailed steps to reproduce the vulnerability.
* **Proof of Concept (PoC)**: A simple code snippet or request that demonstrates the vulnerability, if possible.
* **Impact**: A description of the potential impact of this vulnerability.

We will acknowledge your report as soon as possible and work with you to resolve the issue.

## Disclosure Policy

Upon receiving a security vulnerability report, our goal is to:

1.  **Acknowledge**: Confirm receipt of the report within 3 business days.
2.  **Investigate**: Investigate and validate the vulnerability.
3.  **Remediate**: Develop a fix and prepare for a security release as quickly as possible.
4.  **Disclose**: After the fix is released, we will publicly issue a security advisory and credit the reporter.

We kindly ask that you do not publicly disclose the vulnerability until we have released the fix and advisory on our official channels. This gives our users sufficient time to update.
